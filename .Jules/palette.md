## 2024-05-18 - [Ensure Interactive Overlays are Keyboard Accessible]
**Learning:** When using Tailwind's hover states (like `group-hover:opacity-100`) to reveal interactive elements (e.g., buttons inside an image overlay), those elements become inaccessible to keyboard users because they can tab to the hidden button but won't know they are focused on it.
**Action:** Always pair `group-hover:opacity-100` with `group-focus-within:opacity-100` on the parent container. This ensures that when a user tabs into any interactive element inside the container, the entire overlay reveals itself, keeping the element visible and accessible via keyboard navigation. Additionally, always provide `focus-visible` styling (e.g., `focus-visible:ring-2`) and an `aria-label` for icon-only interactive elements.
