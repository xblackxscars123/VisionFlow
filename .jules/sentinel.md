## 2025-02-27 - [Client-Side Error Leakage & Input Validation Gaps]
**Vulnerability:** The application was exposing full error messages directly to the user interface via `err.message` in the `runPipeline` catch block. Additionally, it lacked file size limits for image uploads and character limits for text prompts, potentially allowing client-side Denial of Service (DoS) attacks via memory exhaustion.
**Learning:** In purely client-side React applications interacting with APIs, error handling often defaults to displaying the raw API response or internal error message to the user. This can inadvertently leak sensitive API context, stack traces, or other internal implementation details. Furthermore, without server-side validation as a backstop, client-side inputs must be strictly bounded to prevent browser memory exhaustion.
**Prevention:** Always implement an error boundary pattern where errors are logged in full internally (`console.error` for client-side) but sanitized into generic, user-friendly messages for the UI. Additionally, always impose strict size limits (e.g., `MAX_FILE_SIZE = 10 * 1024 * 1024` for 10MB) and length limits (e.g., `maxLength={2000}`) on all user inputs, even if they are only processed locally before being sent to an API.
